## 🔧 CONFIGURATION STEPS

### Step 1: Fill Environment Variables

#### A. Production Environment (`.env.prod`)
```bash
cp .env.prod.template .env.prod
nano .env.prod  # Fill in the values marked with TODO
```

**Required values:**
- `AWS_ACCOUNT_ID` - Your 12-digit AWS account ID
- `AWS_REGION` - e.g., `us-east-1`
- `GROQ_API_KEY` through `GROQ_API_KEY_6` - Your Groq API keys
- `GOOGLE_API_KEY` - Your Google Gemini API key
- `CHAT_GOOGLE_API_KEY` - Same as above or separate key

#### B. Staging Environment (`.env.staging`)
```bash
cp .env.staging.template .env.staging
nano .env.staging
```

#### C. Development Environment (`.env.dev`)
```bash
cp .env.dev.template .env.dev
nano .env.dev
```

### Step 2: Configure Terraform Variables

Edit `terraform/environments/prod/terraform.tfvars`:

```bash
cd terraform/environments/prod
cp terraform.tfvars.example terraform.tfvars
nano terraform.tfvars
```

**Fill in:**
- `aws_region` - Your preferred AWS region
- `domain_name` - Your domain for the application (if you have one)
- `ssh_public_key` - Content of your `~/.ssh/id_rsa.pub`

### Step 3: Configure GitHub Secrets

After Terraform creates the infrastructure, add these secrets to GitHub:

```bash
# In your GitHub repository: Settings > Secrets and variables > Actions

# 1. AWS Role ARN (get from Terraform output)
gh secret set AWS_ROLE_ARN --body "$(terraform output -raw github_actions_role_arn)"

# 2. SSH Private Key for Swarm access
gh secret set SSH_PRIVATE_KEY < ~/.ssh/id_rsa

# 3. Environment files (optional - or use AWS Secrets Manager)
gh secret set ENV_PROD < .env.prod
gh secret set ENV_STAGING < .env.staging
gh secret set ENV_DEV < .env.dev
```

### Step 4: Create GitHub Environment

1. Go to: `Settings > Environments > New environment`
2. Name: **production**
3. Add **Required reviewers** (team members who can approve prod deploys)
4. Save

## 🚀 DEPLOYMENT STEPS

### Phase 1: Infrastructure Provisioning (Terraform)

```bash
cd terraform/environments/prod

# Initialize Terraform
terraform init

# Plan infrastructure changes
terraform plan -out=tfplan

# Review the plan carefully
# It will create: VPC, Subnets, EC2 instances, RDS, MSK, ECR, etc.

# Apply infrastructure
terraform apply tfplan

# Save outputs
terraform output -json > ../../../.terraform-outputs.json

# This will take ~15-30 minutes
```

**What gets created:**
- ✅ VPC with public/private subnets across 3 AZs
- ✅ EC2 instances (3 Swarm managers + 6 workers)
- ✅ 5 RDS PostgreSQL databases (user, document, notification, quiz, chat)
- ✅ DocumentDB cluster (MongoDB-compatible)
- ✅ MSK Kafka cluster (3 brokers)
- ✅ S3 bucket for documents
- ✅ ECR repositories for all services
- ✅ Application Load Balancer with SSL
- ✅ Security groups and IAM roles

### Phase 2: Store Secrets in AWS Secrets Manager

```bash
# JWT Secret
aws secretsmanager create-secret \
    --name thoth/prod/jwt_secret \
    --secret-string "$(openssl rand -base64 32)"

# Database passwords (auto-generated by Terraform, or set your own)
aws secretsmanager create-secret \
    --name thoth/prod/user_db_password \
    --secret-string "$(terraform output -raw user_db_password)"

# API Keys
aws secretsmanager create-secret \
    --name thoth/prod/groq_api_key_1 \
    --secret-string "YOUR_GROQ_KEY_1"

# Repeat for all secrets listed in docker-compose.prod.yml
```

**Script provided:** `scripts/setup-secrets.sh` (run after filling values)

### Phase 3: Initialize Docker Swarm

```bash
# Get manager IP from Terraform
MANAGER_IP=$(terraform output -raw swarm_manager_ips | jq -r '.[0]')

# SSH to manager 1
ssh -i ~/.ssh/id_rsa ec2-user@$MANAGER_IP

# Initialize Swarm
docker swarm init --advertise-addr $(hostname -i)

# Get join tokens
docker swarm join-token manager
docker swarm join-token worker

# Exit and join other managers/workers
# (Script provided: scripts/init-swarm.sh)
```

### Phase 4: Deploy Application

```bash
# From your local machine
./scripts/deploy-swarm.sh prod latest

# Or manually:
cd terraform/environments/prod
scp -i ~/.ssh/id_rsa docker-compose.prod.yml .env.prod ec2-user@$MANAGER_IP:/tmp/
ssh -i ~/.ssh/id_rsa ec2-user@$MANAGER_IP
docker stack deploy -c /tmp/docker-compose.prod.yml thoth
```

### Phase 5: Push to GitHub

```bash
# Add all files
git add .

# Commit
git commit -m "feat: Complete AWS deployment infrastructure"

# Push feature branch
git push origin feature/ci-cd-swarm-deployment

# Create Pull Request on GitHub
# After merge to main, CI/CD will take over for future deployments
```

## ✅ POST-DEPLOYMENT VERIFICATION

```bash

aws rds describe-db-instances --query 'DBInstances[*].[DBInstanceIdentifier,Endpoint.Address]'
```

## 🐛 TROUBLESHOOTING

### Terraform Errors

**Error:** "No valid credential sources"
```bash
# Configure AWS CLI
aws configure
# Enter Access Key ID, Secret Access Key, Region
```

**Error:** "Insufficient IAM permissions"
```bash
# Check IAM policy includes:
# EC2, RDS, VPC, MSK, ECR, SecretsManager, IAM (for role creation)
```

### Deployment Errors

**Services won't start:**
```bash
# Check service logs
docker service logs thoth_user-service --tail 100

# Check secrets
docker secret ls

# Verify database connectivity
docker exec <container> ping user-db.<rds-endpoint>
```

**Database connection failures:**
```bash
# Check security group rules
aws ec2 describe-security-groups --group-ids <sg-id>

# Verify RDS endpoint
aws rds describe-db-instances --db-instance-identifier thoth-user-db
```
